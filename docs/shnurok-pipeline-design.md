# Маршрут «shnurok» — дизайн

**Дата:** 2026-08-07
**Статус:** согласован (ждёт вычитки спеки перед планом реализации)
**Референс-сборки, на которых обкатан стиль:** `output/shnurok_test/v5/` (`final_classic.mp4`, `final_bold.mp4`), исходники в `assets/shnurok_test/`.

---

## 1. Цель

Отдельный маршрут flexi для сборки вертикальных рекламных рилсов кроссовок в стиле
NUMERIS/SHNUROK. Клиентский заказ: «научиться делать такие видосики на потоке».

**Главный принцип — агент-центричность, а не жёсткий конфиг.** Работает как весь
flexi сейчас: оператор кидает исходники в папку и говорит «собери shnurok» — агент
сам разбирает материал, определяет структуру и собирает. Оркестровку (что куда,
тайминги, порядок b-roll, момент влёта графики) решает **агент по ситуации**;
конфиг держит только фирменный стиль и редкие оверрайды.

**Кто рулит:** другой агент (скорее всего Codex от OpenAI), за рулём человек.
Человек кидает файлы в папки и забирает готовые видео. Репозиторий публичный на
GitHub. Отсюда требование: маршрут самодокументирован для стороннего агента
(плейбук простым языком), с предсказуемыми стадиями и понятными логами.

---

## 2. Что собираем (структура ролика)

Вертикаль 9:16, 1080×1920, 30fps, ~50 сек. Три части:

1. **Хук** — говорящая голова (автор в камеру) + крупные титры-лесенка;
   на слове-триггере влетает графика (напр. машина на слове «машины»), опционально
   последнее слово уходит **за голову** автора (text-behind-subject).
2. **Тело** — b-roll (продуктовые/брендовые клипы) под **чистую озвучку**; b-roll
   идёт немым, озвучка кладётся поверх; пословные субтитры по центру, синхронные речи.
3. **CTA** — снова говорящая голова + крупные титры (стек справа-вверх, копятся
   экранами).

Два визуальных стиля на выходе:
- **classic** — белые ровные титры, плавные кроссфейды, медленные наезды;
- **bold** — красные акценты на ключевых словах, лёгкий наклон титров, белые флеши
  и кроп-панчи в теле, пословные сабы капсом.

По умолчанию собираем оба (агент может собрать один по просьбе).

## 3. Как агент работает (плейбук)

1. **Инвентаризация.** Оператор кидает исходники в папку (переиспользуем инбокс
   `raw/`, агент сортирует — как уже принято в flexi). Агент `ffprobe`-ит всё:
   какие клипы — говорящая голова, что — b-roll, где VO-дорожка, музыка, картинки
   для графики. Ориентацию iPhone-клипов проверяет по кадру, не по метаданным.
2. **Определение структуры.** Агент сам понимает из материала и разговора: первый
   «говорящая голова» → хук, b-roll под озвучку → тело, второй «говорящая голова»
   (или хвост того же клипа) → CTA. Готового референс-видео обычно нет — стиль
   зашит в плейбук/дефолты, копировать не с чего.
3. **Правила по умолчанию:**
   - озвучка тела — **поверх**, b-roll немой под ней; тайминг ведёт озвучка;
   - **субтитры берутся из озвучки** (faster-whisper, word-level) и синхронятся к
     ней, ложатся на видео; вокабуляр правится через `config.yaml → subtitle_corrections`
     + пер-ролик `corrections`;
   - хук/CTA — крупные титры (лесенка / стек), текст **авто из речи** хука/CTA
     (+corrections), с возможностью полного override, если распознавание промахнулось;
   - тело — пословные сабы **без наложения**: каждое слово держится ровно до начала
     следующего (`end = next_start − 0.02с`), без хвоста;
   - графика влетает на **слове-триггере**: автор сказал «тут машина» → туда; не
     сказал → агент предлагает момент и показывает;
   - опционально «текст за головой» на слове-триггере (u2net-сегментация);
   - громкость сводится по ebur128 (см. [[ffmpeg-loudness-ebur128-vs-loudnorm]] в памяти).
4. **Сборка** по стадиям (см. §4), затем **QA** (§6), затем версионированный вывод.
5. **Показ.** Агент отдаёт финалы и коротко проговаривает принятые решения (где
   влетела графика, что попало в дубли-гейт и т.п.).

Автор может бросить реплику по ходу («вот тут выедет машина», «сделай дерзко») —
агент учитывает. Иначе — решает сам и предлагает.

## 4. Стадии пайплайна (модули)

`ingest → transcribe → titles → graphic → hook-render → body-render → cta-render → assemble → qa → output`

Каждая — отдельная функция, логирует что сделала; при падении видно на какой стадии.
Стадии — не жёсткий монолит: агент может вызвать нужные по отдельности.

Раскладка кода: движковые утилиты (§5) — в `src/shnurok/` (модуль библиотеки,
переиспользуется как остальной `src/`); оркестратор-обёртка и плейбук — в
`pipelines/shnurok/`. Точка входа в духе `python -m src.cli shnurok <folder>` —
удобная обёртка, а не единственный способ; агент может собирать и покусочно,
вызывая утилиты по отдельности.

## 5. Готовые инструменты (переиспользуемые утилиты)

Тяжёлые и ошибкоопасные куски вынесены в отдельные функции/подкоманды, чтобы агент
их **вызывал, а не переписывал** каждый раз:

- **Вырез графики** — чистый alpha-cutout заливкой фона от углов + сжатие альфы
  (colorkey оставляет белый ореол — так НЕ делать), тугая обрезка по границам,
  мягкая тень. Вход: любое фото на однотонном фоне.
- **Маска «текст за головой»** — покадровая сегментация человека `rembg`
  (`u2net_human_seg`) на окне хука → matte; композит: фон → текст → человек поверх.
  ~4с/кадр на CPU (окно хука ~5с ≈ несколько минут); модель качается один раз.
- **Титры-лесенка / стек** — генератор ASS: хук (лесенка влево, плотный шаг ~108,
  pop-in), CTA (стек справа-вверх, копится экранами), стиль по classic/bold.
- **Пословные сабы** — из word-level транскрипта, без наложения (`end = next−0.02`).
- **Хук-композит** — сборка: говорящая голова + текст-за-головой + matte + передние
  титры + влёт графики (заезд, размер/позиция, тайминг).
- **Громкость** — сведение речь+музыка по ebur128 с лимитером.

Переиспользуем из движка flexi: версионирование вывода (`src/output_paths.py`),
транскрипцию (`src/transcribe.py`), подбор/нормализацию b-roll
(`src/broll_library.py`, `broll_picker.py`), сборку (`src/assembly.py`),
хелперы субтитров (`src/subtitles.py`).

**Новая зависимость:** `rembg` (u2net) в `requirements.txt`.

## 6. QA-гейты (обязательны перед «готово»)

- формат/длительность/ориентация (кадр с горизонтом, не метаданные);
- пословные сабы — на экране всегда **одно** слово (нет наложения);
- **аудио-дедуп**: транскрипт финальной дорожки читается из конца в конец, без
  задвоений и срезанных слов (см. [[talking-head-dedup-review]] в памяти);
- влёт графики попал на слово-триггер; «текст за головой» не рвётся по краю маски.

QA-скрипт: `pipelines/qa_shnurok.py`.

---

## 7. Стиль-дефолты — `config.yaml → shnurok:`

Один раз выносим фирменный стиль (меняется редко, не на ролик):
шрифты (Gilroy Heavy/Bold), размеры и шаг строк (~108), цвета и акцент (красный
`#D5342F`/BGR `2F34D5`), тайминги и размер/позиция влёта графики, параметры
«текста за головой», переходы classic/bold (кроссфейд/наезд vs флеш/панч),
целевая громкость. Пер-ролик оверрайды — минимальны и опциональны.

---

## 8. Все правки из этого диалога — как поведение по умолчанию

- плотный межстрочный в хуке и CTA;
- чистый вырез графики (без ореола), меньше и ниже — лицо автора открыто;
- ключевое слово сдвинуто правее и **за голову**;
- CTA со всеми строками (в т.ч. «БЕЗ ПОПЫТОК»), плотный шаг, строки экрана держатся
  вместе;
- пословные сабы без наложения;
- аудио-дедуп-гейт перед выдачей.

Полный свод стиля — в памяти [[shnurok-preset]].

## 10. Явно вне объёма (YAGNI)

- жёсткий обязательный пер-ролик `shnurok.yaml` — **не делаем**, оркестрация у агента;
- генерация озвучки (TTS) — **не сейчас**: озвучку тела даёт клиент готовым файлом;
- клиентский UI — **не сейчас**;
- копирование по референс-видео — не требуется, стиль зашит в дефолты.

---

## 11. Открытые мелочи (решаются при реализации, не блокируют)

- хук+CTA приходят одним клипом (агент находит окна по речи) или двумя файлами —
  поддержать оба варианта, автоопределение;
- имя автора/бренда, которое Whisper стабильно слышит неверно (напр. «Кенри/Кенле
  Джонс») — занести в `corrections` по умолчанию для этого клиента.
