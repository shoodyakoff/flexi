# Пайплайн 3-strip

Воспроизводимый монтаж дня съёмки на телефон в вертикальный рилс 9:16 в формате
«3-strip» (три горизонтальных клипа, сложенных стопкой, асинхронный каскад).
Один конфиг на эпизод; движок + QA переиспользуются. Полный свод правил в
[RULES.md](RULES.md).

```
three_strip/
  build_3strip.zsh     # ДВИЖОК — управляется конфигом, не править под эпизод
  qa.py                # слой QA — скриншоты + авто-проверка критериев приёмки
  analyze.zsh          # хелпер — плотный контактный лист с таймкодами для длинного клипа
  RULES.md             # свод правил монтажа (источник истины)
  episodes/
    example.conf       # эпизод = единственный файл, который вы пишете/правите (скопируйте его)
```

## Запуск
```sh
# 1) разобраться с длинным клипом (опционально, пока пишете монтаж):
RAW=raw/myday zsh analyze.zsh 4907   # -> output/analyze/4907/sheet.png + scene cuts

# 2) собрать рилс из конфига эпизода (рендерит + авто-запускает QA):
zsh build_3strip.zsh episodes/example.conf
#    -> <OUT>/<NAME>.mp4 + qa_report.txt + qa_sheet.png
```
Плитки кэшируются по (clip,in,dur); повторный запуск после небольшой правки
занимает секунды.

## Рабочий процесс для НОВОГО дня
1. **Ingest**: сложите клипы в `raw/<day>/`. Скопируйте `episodes/example.conf` → `<day>.conf`,
   задайте `NAME/RAW/OUT/MUSIC`.
2. **Diff**: перечислите клипы; отметьте те, что пользователь удалил (не использовать), и новые.
3. **Orient**: для каждого клипа проверьте вертикальность глазами (RAW против авто — теги врут).
   POV-клипы: проверяйте кадр с горизонтом, а не середину. Соберите развороты на 180
   в `NEED180`.
4. **Analyze** длинные клипы (`analyze.zsh <num>`); выберите 1+ фрагментов (демо→использование,
   раскрытие, ключевой момент).
5. **Author** монтаж в конфиге: заполните `MID/TOP/BOT` хронологически,
   с выравниванием по индексу (одинаковый DUR на колонку), каждый клип один раз, лица редко, демо→использование
   рядом в одной полосе, максимум 1 экран на колонку, никогда не 3 похожих в колонке.
   Задайте подложку `OUTRO_*`.
6. **Build** → движок рендерит + запускает QA.
7. **QA loop**: прочитайте `qa_report.txt`; если проверка FAIL, исправьте эту колонку в
   конфиге и пересоберите (из кэша → быстро). Осмотрите `qa_sheet.png` (🟥 дубль, 🟩 лицо)
   на ориентацию/центрирование/цвет. Выпускайте только при всех PASS.

## Ключи конфига (эпизод)
| ключ | значение |
|-----|---------|
| `NAME/RAW/OUT` | id эпизода, папка-источник, папка вывода |
| `WORK` | директория кэша плиток (по умолчанию `$OUT/work_$NAME`) |
| `MAX_DUR` | ограничение длины (45) |
| `NEED180` | список клипов через пробел для разворота на 180° |
| `MUSIC/MUSIC_START/MUSIC_VOL` | трек, смещение старта (с), громкость |
| `LEAD_top/LEAD_bot` | смещения каскада (0.5 / 1.0) |
| `MID/TOP/BOT` | таймлайны по полосам, записи `"IMGNUM IN DUR"`, с выравниванием по индексу |
| `ENDLEN`+`OUTRO_TOP/BOT/CTR`(+`_VIS`) | концовка с каскадным выходом на подложке (0 = нет) |

## Значения по умолчанию (подтверждены)
- Длина ≤ **45s**. Лица **редко**. **Без повторов** (каждый клип один раз).
- Каскад 3-strip; тонмаппинг HDR→SDR; звук источника выключен; подложка-обрамление (начало и конец на подложке).
- «лица часто / переиспользование клипов» — это альтернативный режим — просто добавьте больше записей с лицами / повторите клипы в конфиге.

## Критерии приёмки (авто-проверка через qa.py)
формат 1080×1920·30fps·audio · длительность≤MAX · **no-3-same** (phash≥10) ·
зазор-между-лицами (rare-mode: информационно) · нет мёртвой полосы (вне intro/outro).
Визуально (qa_sheet): ориентация вертикальная, действие по центру, цвет, финал на подложке.
