# shnurok — плейбук агента

Маршрут **shnurok** (RU-имя в `CLAUDE.md`: **shnurok** / «рекламный рилс
кроссовок») собирает вертикальный рекламный рилс в стиле NUMERIS/SHNUROK:
хук на говорящей голове → тело на b-roll под клиентскую озвучку → CTA снова
на говорящей голове. Формат — 1080×1920, 30fps. На выходе два визуальных
стиля: **classic** (белые ровные титры, наезд/фейд) и **bold** (красные
акценты, наклон титров, флеши и кроп-панчи в теле). По умолчанию собираются
оба.

Движковый код — `src/shnurok/` (переиспользуемая библиотека). Этот файл —
плейбук: как оператору/агенту скормить исходники и получить готовый рилс.
Дизайн-документ с обоснованием решений: `../../docs/shnurok-pipeline-design.md`.

---

## Контракт папки

`build_shnurok(folder, ...)` (и CLI `shnurok <folder>`) ждёт **одну папку со
всеми исходниками ОДНОГО ролика** — это не общий инбокс `raw/`,
рассортированный по типам в `assets/*` (как для остальных маршрутов из
`CLAUDE.md`). Имя папки (`folder.name`) становится slug'ом рендера —
`output/<folder.name>/vN/`.

Что кладётся в папку одного job'а:
- клип(ы) говорящей головы — из него же берутся окна **хука** и **CTA**
  (по умолчанию это один клип: сначала хук, потом пауза, потом CTA);
- файл озвучки тела — **готовый клиентский** файл (TTS в этом маршруте не
  генерируется, он приходит извне);
- клип(ы) b-roll (продукт/демо);
- опционально картинка для графики-влёта (PNG/JPG на светлом/белом фоне —
  вырез фона работает по заливке от углов, см. «Стадии» ниже);
- опционально музыка (если её нет — берётся дефолт `assets/music/provocative.mp3`).

Референсный набор исходников, на котором обкатан стиль, лежит в
`assets/shnurok_test/` — см. «Пример» ниже.

## Как агент определяет структуру — и почему лучше указывать источники явно

Если какой-то из источников не передан явно, `build_shnurok` вызывает
`inventory(folder)` (`src/shnurok/structure.py`) как **fallback**-угадайку:
картинки → `graphic`; аудио-файл → `music` (если в имени есть
`music`/`bgm`/`track`) иначе `voice`; видео **с** аудиодорожкой →
`talking_head`; видео **без** аудиодорожки → `broll`.

Проблема: снятые с рук продуктовые/демо-клипы почти всегда несут аудио
(шум окружения на встроенный микрофон) — значит `inventory()` кладёт их в
`talking_head`, а не в `broll`. Туда же попадёт и скачанный референс/клип
для вдохновения (например, сохранённый рилс), если в папке случайно
остался — у него тоже есть звуковая дорожка. В итоге в `talking_head`
может оказаться несколько кандидатов, и функция вынуждена гадать:
`_pick_talking_head` предпочитает clip'ы с именами как у камеры
(`IMG_####`, `MVI_####`, `DJI_####`, `GOPRO####`) всему остальному, берёт
первый по алфавиту и печатает предупреждение `⚠`, когда кандидатов больше
одного. `_broll_fallback` потом добирает пул b-roll из оставшихся
camera-native клипов бакета `talking_head`.

**Правило:** агент, который раскладывал `raw/` по правилам инбокса
`CLAUDE.md`, уже знает структуру папки job'а — поэтому он должен вызывать
`build_shnurok(...)` (Python, не CLI — см. «Точка входа» ниже) с явными
`talking_head=`, `voice=`, `broll=[...]`, `graphic=`, `music=`. Автоугадывание
— это запасной путь для быстрого/неприсмотренного прогона, а не надёжный
способ понять структуру; если появилось предупреждение `⚠`, релиз нельзя
считать корректным без проверки.

## Правила по умолчанию

- Озвучка тела кладётся **поверх** b-roll; b-roll идёт немым под ней;
  тайминг тела ведёт длительность файла озвучки.
- **Субтитры тела берутся из озвучки** (пословный транскрипт через
  `src.transcribe`) и синхронятся к ней; вокабуляр правится через
  `config.yaml → subtitle_corrections`. Сабы — **без наложения**: каждое
  слово держится до начала следующего минус зазор (`end = next_start − 0.02с`).
- Крупные титры хука/CTA — **авто из речи** говорящей головы (+corrections),
  с возможностью полной замены (см. «Известные ограничения»).
- Графика влетает на **окне-триггере**: по умолчанию окно вычисляется как
  доля длительности хука (35%–90%); агент может назвать конкретное слово и
  подставить своё окно, вызывая `compose_hook(...)` напрямую.
- Громкость сводится по ebur128 (не `loudnorm` — см. память
  `[[ffmpeg-loudness-ebur128-vs-loudnorm]]`), с лимитером на выходе.

## Стадии

`build_shnurok` (`src/shnurok/build.py`) прогоняет их последовательно на
каждый стиль (кроме общих для обоих стилей шагов — транскрипции, сплита
хук/CTA, выреза графики):

1. **ingest** — явные источники или `inventory()`-fallback (см. выше).
2. **transcribe** — пословный транскрипт говорящей головы и озвучки
   (`src.transcribe.transcribe`).
3. **split hook/cta** — `structure.split_hook_cta`: разрыв по паузе >1.5с
   в словах говорящей головы делит клип на хук (первый непрерывный забег) и
   CTA (весь хвост, включая внутренние паузы длиннее порога).
4. **hook titles** — `titleplan.plan_screens` (общий и для хука, и для CTA):
   режет речь на смысловые экраны по пунктуации транскрипта, каждый экран
   бьёт на строки-лесенку ПО ШИРИНЕ кадра (не по числу слов) с клампом x
   (без обрезки), склеивает дефисные токены («кому»+«-то»→«кому-то»);
   `titles.screens_titles_ass` рендерит лесенку слева (an7). Хук: экран
   «…машины?» гаснет до «тогда смотри!».
5. **graphic cutout** — `cutout.cutout_graphic`: alpha-вырез заливкой фона
   от углов (не colorkey — тот оставляет ореол), эрозия альфы на 1px, тугая
   обрезка по bbox, мягкая тень.
6. **hook render** — `hook_compose.compose_hook`: говорящая голова,
   передние титры (burn ASS), влёт графики окном `(0.35×hook_dur,
   0.90×hook_dur)`. **Текст за головой в авто-сборке не используется**
   (см. «Известные ограничения»).
7. **body render** — `render_body.render_body`: b-roll делится на равные
   слайсы `body_dur / len(broll)`, каждый клип зацикливается на свой слайс
   (`enc_cut(..., loop=True)`), эффекты по стилю (`bold`: флеш-белым на
   каждом клипе + кроп-панч на каждом 4-м; `classic`: медленный наезд, если
   слайс ≥1.9с), склейка **хард-катом**.
8. **cta render** — `render_cta.render_cta`: прямой вырез окна CTA из
   говорящей головы (+флеш для `bold`).
9. **assemble** — конкатенация hook+body+cta в немое видео.
10. **body subs** — `word_subs.word_subs_ass`: пословные сабы без
    наложения, синхронные окну тела.
11. **cta titles** — `titleplan.plan_screens` + `titles.screens_titles_ass`:
    те же смысловые экраны и лесенка слева, что и в хуке (единый вид);
    экраны сменяются по ходу речи, строки экрана гаснут вместе.
12. **audio mix** — `audio_mix.mix_voice_music`: сегменты (хук-аудио TH +
    голос тела + CTA-аудио TH) выравниваются по громкости ebur128 до
    `style.sub_lufs`, музыка зацикливается и приглушается до
    `style.music_lufs` с фейд-аутом 1.2с, сведение через `amix` + `alimiter`.
13. **final mux** — burn `body_subs` + `cta_titles` на немое видео, мукс со
    сведённой дорожкой, `faststart`.
14. **output** — запись в `output/<slug>/vN/final_<style>.mp4` +
    обновление симлинка `latest` (`src/output_paths.py`).

## Точка входа

CLI-обёртка (только авто-инвентаризация — явных флагов на источники у неё
нет):

```bash
python -m src.cli shnurok <folder> --style classic|bold|both   # по умолчанию both
```

Когда структуру папки уже знаешь (а агент, разложивший `raw/`, знает
всегда) — вызывай `build_shnurok` напрямую из Python с явными источниками:

```python
from src.shnurok.build import build_shnurok

outs = build_shnurok(
    "<folder>",
    styles=("classic", "bold"),
    talking_head="<folder>/<говорящая_голова>.mp4",
    voice="<folder>/<озвучка>.m4a",
    graphic="<folder>/<картинка>.jpg",       # опционально
    broll=["<folder>/<broll_1>.mp4", "..."],
    music="<folder>/<музыка>.mp3",           # опционально, иначе дефолт из config.yaml
)
```

Сигнатура (`src/shnurok/build.py`):
`build_shnurok(folder, styles=("classic","bold"), config_path="config.yaml", talking_head=None, voice=None, broll=None, graphic=None, music=None) -> dict[str, Path]`.
Пути в `talking_head`/`voice`/`broll`/`graphic`/`music` резолвятся
относительно `folder`, если не абсолютные.

## Известные ограничения

- **«Текст за головой» выключен в авто-сборке.** `build_shnurok` никогда не
  передаёт `behind_ass`/матт в `compose_hook` — этот эффект доступен только
  через прямой вызов `compose_hook(...)` с маттом от
  `matte.person_matte(...)` (посегментная u2net-сегментация человека,
  ~4с/кадр на CPU — окно хука на несколько секунд занимает пару минут).
  Включать его — осознанное решение агента для конкретного кадра, не
  дефолт.
- **`classic` реально режет хард-катом, не кроссфейдом.** В
  `config.yaml → shnurok.styles.classic.transitions` стоит `crossfade`, но
  ни `render_body`, ни финальная склейка это поле пока не читают — везде
  используется конкатенация без перехода. Плавные переходы — будущее
  улучшение, не то, что уже работает.
- **Авто-разбивка титров — экраны по пунктуации, строки по ширине.**
  `titleplan.plan_screens` делит на экраны по знакам препинания транскрипта
  и бьёт строки по ширине кадра. Это заметно лучше, чем по числу слов, но
  всё же зависит от того, как Whisper расставил запятые/точки: если в
  конкретном ролике перенос лёг не по смыслу, задай титры вручную —
  собери список экранов `[[(start,end,TEXT,x,y),...],...]` сам и отрендерь
  через `titles.screens_titles_ass`, минуя `plan_screens`.
- **Автоопределение говорящей головы/b-roll может угадать неверно**, когда
  в папке больше одного клипа со звуковой дорожкой (см. раздел выше) —
  всегда проверяй `⚠`-предупреждение в логе или, лучше, не давай поводу
  появиться, передавая источники явно.
- **Шрифты Gilroy.** Стиль ссылается на семейства `Gilroy Heavy`/`Gilroy
  Bold` (`config.yaml → shnurok.styles`). Если этих TTF нет в
  `assets/fonts/`, libass молча подставляет фолбэк-шрифт — рендер не
  упадёт, но не будет похож на референс. Для точного вида положи
  лицензионные Gilroy TTF в `assets/fonts/`.

## QA (обязательно перед «готово»)

```bash
python pipelines/qa_shnurok.py --slug <slug>              # latest версия
python pipelines/qa_shnurok.py --slug <slug> --version vN # конкретная версия
```

Проверяет:
- **WORD_SUBS** — пословные сабы тела без наложения (`end[i] <= start[i+1]`);
- **FORMAT** — 1080×1920, длительность (`ffprobe`);
- **DEDUP** — транскрибирует финальную сведённую дорожку и ловит
  **буквально задвоенные** слова подряд (длиной ≥4 символов).

**Обязательный гейт аудио-дедупа (не пропускать, пока не проверено
вручную).** `qa_shnurok.py`'s DEDUP ловит только точное повторение одного и
того же слова — он **не** ловит спикера, который **пересказывает ту же
мысль другими словами** или **запинается и повторяет часть фразы**. Поэтому
перед тем как сказать «готово»: транскрибируй финальный `final_<style>.mp4`
целиком и **прочитай транскрипт от начала до конца** — если нашёл повтор
мысли или запинку, отрежь его явными правками на уровне исходных клипов
(например, обрежь окно CTA/хука или отредактируй `voice`-файл) и
перерендери. Это то же правило, что для говорящей головы (см. `CLAUDE.md` →
«MANDATORY audio-dedup gate»), просто применённое к `qa_shnurok.py` вместо
`qa_talking_head.py`.

## Пример: `assets/shnurok_test/`

Референсный набор исходников (один job, всё в одной папке — как и
предписывает контракт папки выше):

| Файл | Роль |
|---|---|
| `IMG_3968.MOV` | говорящая голова (хук + CTA) |
| `Numeris.m4a` | озвучка тела (клиентская) |
| `IMG_9585.JPG` | картинка для графики-влёта |
| `IMG_9575/9576/9577/9578/9580/9581/9582.MP4` | b-roll (несут собственный звук — авто-инвентаризация без явных `broll=` спутала бы их с говорящей головой) |
| `IMG_9588.JPG`, `IMG_9589.JPG` | в этом job'е не используются |
| `SnapInsta.to_....mp4` | скачанный референс/вдохновение, **не источник** — тоже со звуком, поэтому оставлять его в папке для авто-режима рискованно (см. раздел про автоопределение) |

Явный вызов (Python — так и делает интеграционный тест
`tests/test_shnurok_build.py`):

```python
from src.shnurok.build import build_shnurok

outs = build_shnurok(
    "assets/shnurok_test",
    styles=("classic", "bold"),
    talking_head="assets/shnurok_test/IMG_3968.MOV",
    voice="assets/shnurok_test/Numeris.m4a",
    graphic="assets/shnurok_test/IMG_9585.JPG",
    broll=[f"assets/shnurok_test/IMG_{n}.MP4" for n in (9575, 9576, 9577, 9578, 9580, 9581, 9582)],
)
# outs == {"classic": Path("output/shnurok_test/v<N>/final_classic.mp4"),
#          "bold":    Path("output/shnurok_test/v<N>/final_bold.mp4")}
```

CLI-эквивалент (работает только потому, что `IMG_3968` по алфавиту раньше
`IMG_9575...` — случайность именования, не гарантия; для новой папки job'а
предпочитай явный Python-вызов выше):

```bash
python -m src.cli shnurok assets/shnurok_test --style both
```

QA после рендера:

```bash
python pipelines/qa_shnurok.py --slug shnurok_test
```

плюс ручная проверка транскрипта финального аудио от начала до конца (см.
«QA» выше).
